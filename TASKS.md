## Заметки
- Firefox отдаёт метаданные с мусором: на каждой смене трека он чередует
  настоящий кадр с плейсхолдером (заголовок вкладки, пустой артист) и
  выставляет `mpris:artUrl` лишь чтобы через ~15 мс его стереть. Из-за
  этого моргали и обложка, и название. `Media.qml` теперь защёлкивает
  последний валидный кадр: кадр с пустым артистом (у плеера, который
  раньше артиста давал) отбрасывается целиком, а `artUrl` присваивается
  только из непустого значения. Признак мусора — пустой `xesam:artist`
  при непустом раньше (см. лог `artflow3.log`: T=[Yandex Music…] A=[]).
  Проверено серией из 14 кадров в момент перехода — обложка/название
  стабильны, промежуточных пустых кадров нет.
- `AlbumArt.qml`: `retainWhileLoading` держит прошлый кадр во время
  загрузки; запасная иконка при `Image.Null` **и** `Image.Error` (не
  только пустой URL — иначе неудачная загрузка = пустой квадрат).
- Старые файлы обложек Firefox удаляет (`~/.config/mozilla/firefox/
  firefox-mpris/`), поэтому при смене трека `artUrl` сбрасывается в "",
  а не тянется от прошлого трека — иначе была бы битая картинка.
- Датчик CPU резолвится по имени драйвера (k10temp/coretemp/zenpower),
  а не по пути — индекс hwmon плавает между загрузками.
- Десктопная панель click-through везде, кроме карточки плеера
  (`mask: Region { item: mediaCard }`).
- Свечения за большими часами быть не должно: `RectangularShadow` рисует
  настоящий прямоугольник, а `layer.enabled` + `MultiEffect` оставляет
  дымку по границам текстуры слоя. Оба варианта читались как «квадрат».
- Рывок при скрытии панелей был от `easeEmphasized` (decelerate) на
  выходе: прозрачность быстро падала до ~0.1 и там зависала, а окно
  демапилось (`hideDelay` = длине анимации) — доскок 0.1→0. Теперь easing
  зависит от направления: вход decelerate/spring, выход `easeExit`
  (accelerate, `Theme.animExit` = 170мс) доходит до настоящего 0 до
  демапа. Значение open-состояния уже защёлкнуто к моменту срабатывания
  Behavior, поэтому одна кривая читает «вход» vs «выход» правильно.
- Обои рисует сам quickshell (`WallpaperView.qml`, background-слой), а не
  swaybg — тот резал картинку жёстко. Кросс-фейд по схеме base+overlay:
  новые обои грузятся в overlay поверх, плавно проявляются, и лишь когда
  base догрузил ту же картинку снизу — overlay гасится (иначе мелькал бы
  полузагруженный кадр). Схема «два флип-флоп изображения с bound-opacity»
  давала жёсткую подмену — НЕ использовать.
- Цвета переехали с `GeneratedColors.qml` на `generated-colors.json`
  (`FileView` + `watchChanges`): переписывание `.qml` в конфиг-директории
  вызывает полный reload (пересоздание всех окон), а `.json` подхватывается
  вживую → палитра плавно перетекает (`Behavior on color`) в такт с
  обоями. Проверено: `.json` в конфиг-директории reload НЕ триггерит.
  Хук `reload-quickshell` в wallust убран, swaybg убран из автозапуска.
- Обои НЕ биндить к `Wallpaper.path` напрямую в `WallpaperView` — биндинг
  перезагрузит видимую картинку сразу и убьёт фейд. Источники ставятся
  императивно. FrostedBackground/CheatSheet биндить можно (им фейд не
  нужен, только пересемплить блюр).

## Сессия 8 (краш + сеть)
- [x] КРАШ при быстром next→previous — воспроизведён (20-25 циклов
      playerctl next/previous без задержки убивали qs, в логе НИ ОДНОЙ

      удалённые Firefox'ом файлы обложек, ×2 инстанса (MediaOsd+DesktopClock).
      Фикс: дебаунс `_sync()` в `Media.qml` (Timer 90мс) — churn метаданных
      схлопывается в одно обновление, загрузчик не дёргается. Проверено:
      60+40 переключений — qs жив, RSS стабилен. (Метод: временно source=""
      в AlbumArt → выжил → подтвердил виновника.)
- [x] СЕТЬ постоянно прерывается — причина: бар каждые 10с гнал
      `nmcli -t -f active,signal dev wifi`, а это просит NetworkManager
      ПЕРЕСКАНИРОВАТЬ эфир; скан на одноядерной карте подвешивает соединение.
      Фикс: `iw dev <if> link` (читает текущую ассоциацию, БЕЗ скана),
      dBm→проценты (2*(dBm+100)). Других scan-вызовов в шелле нет (нативный
      Networking трогает список сетей только при раскрытии wifi в ЦУ).

## Сессия 9 (продолжение): меню не рисовались вообще

Конфиг грузился без единой ошибки, данные из DBus приходили — но НИ ОДНО меню

- [x] 55. **Ширина меню считалась через саму себя.** `contentWidth:

      `TextMetrics` по тексту пунктов и присваивается (`onModelChanged`), а не
      биндится. Высоту брать из layout можно — высоты строк константные.
- [x] 56. **`target: parent` в анимации внутри делегата.** `SequentialAnimation`

      анимации уже адресовались по id, баг был только в `ActionMenu`.

      contentWidth + 20` учитывал только тень (10+10), но не 6px инсет

- [x] 58. **`onOpenChanged` не срабатывает для значения, заданного при

## Сессия 10 (по отзыву: зависшие тосты, запись, портал)

- [x] 64. **Пустые тосты, которые не убирались.** Две причины сразу:

### Ловушки, стоившие времени

- **Свойство, имя которого начинается с `on`, ломает своё же уведомление.**
  `readonly property bool onPage: page !== ""` рядом со свойством `page`:
  `onPageChanged` — одновременно обработчик `page` и нотификатор `onPage`,
  и биндинг молча перестаёт пересчитываться. Страница просто не открывалась.
  Переименовано в `showingPage`.
- **Панель, загружаемая лениво, пропускает сигнал, который её загрузил.**
  `Connections { onXOpenChanged }` внутри компонента не сработает при первом
  открытии — сигнал уже был испущен. Нужен парный вызов из
  `Component.onCompleted`.
- **Биндинг + обработчик записи обратно = петля.** `property x: Prefs.get(k)`
  вместе с `onXChanged: Prefs.set(k, x)` зацикливается, потому что запись
  меняет объект, который читает биндинг. Читать из `Prefs` нужно один раз.
- **`Rectangle { clip: true }` обрезает по прямоугольнику** и игнорирует
  `radius`. Для скруглённой обрезки есть только `ClippingRectangle`.
- **`FileView.setText()` — это и есть запись**, отдельного `save()` нет;
  `writeAdapter()` работает только с адаптером.
- **Долгоживущий экземпляр `qs` теряет IPC.** После ~29 горячих перезагрузок
  за 9 часов `qs ipc` начал отвечать `Not ready to accept queries yet`, хотя в
  логе было `Configuration Loaded`. Лечится перезапуском оболочки; при этом
  перестают работать и биндинги niri, которые ходят через `qs ipc call`.
- **Полноэкранное окно рисуется поверх слоя Top.** Панель может быть открыта и
  не видна на скриншоте — это не баг оболочки.

## Сессия 12: yworld

`mihomo-gui` переименован в **yworld** и переехал в `~/yworld`. Имя больше
ничего не описывало: GTK-окна нет с прошлой сессии, а это бэкенд под панелью
оболочки. Пакет `yworld`, лаунчер `~/.local/bin/yworld`, `pyproject.toml`,
`README.md`. QML-синглтоны `Mihomo`/`MihomoApi` названий не сменили — они
обёртка вокруг самого mihomo, а не вокруг проекта.

### Что было сломано в бэкенде

Права и хранилище:
- `subscriptions.json` и все `*-config.yaml` были **644**. В первом — токены
  доступа провайдеров, во втором — UUID и пароли нод. Теперь 600 и атомарная
  запись; файлы от старой версии подтягиваются при первой же загрузке.
- Битый `subscriptions.json` возвращал `{}`, и следующий `add` писал поверх
  него новый файл — восстановимое повреждение превращалось в безвозвратную
  потерю всех ссылок. Повреждённый файл теперь отводится в сторону.
- Имя подписки шло в имя файла без проверки: `sub-add "../x"` писал вне
  каталога.

Процесс:
- `_stop_pid` звал `killpg(pid)`, что верно, только пока pid возглавляет свою
  группу. Проверяется по `/proc/pid/stat`.
- Удаление активной подписки оставляло работающий туннель без конфига на диске.
- `start` без имени поднимал первую по алфавиту, а не последнюю рабочую
  (`last.json`).
- Ничто не сериализовало start/stop — два вызова гонялись за один конфиг и
  маркер. Добавлен `flock`.
- `start` делал 12-секундную проверку выхода до того, как mihomo докачал
  rule-providers: и втрое дольше заявленных 7.5 с, и ответ неверный. Вынесено
  в `yworld check`.

Подписки и ссылки:
- Первый непустой Clash-ответ обрывал перебор User-Agent. Панель, отдающая
  Clash-клиентам три ноды вместо пятидесяти, принималась на веру.
- `_scrub` подменял только точную строку URL, а requests печатает
  нормализованный адрес — **токен утекал в текст ошибки на экран**. Поймано
  написанным тестом, а не глазами.
- `subscription-userinfo` строил `datetime`, который упал бы в `json.dump`.
  Квота и срок теперь int, хранятся в подписке и показываются в панели.
- REALITY-ссылка без `pbk` давала конфиг, который mihomo отвергает целиком —
  вместе со всеми остальными нодами. Такие ноды выбрасываются.
- hysteria2/hy2, tuic и ss-плагины молча терялись; `alpn` и `packet-encoding`
  не переносились из ссылок, которые их несут.

Безопасность:
- Контроллер mihomo по умолчанию принимает **любой Origin**. Любая открытая
  вкладка могла переключать ноды, читать список соединений и гасить туннель
  через loopback. Конфиг теперь ставит `external-controller-cors` с пустым
  списком источников. Ничто в проекте не шлёт Origin, так что это бесплатно.

99 тестов на stdlib `unittest` — `python3 -m unittest discover -s tests -t .`,
ставить нечего.

### Почему половина нод не работает

Жалоба «на телефоне работает, тут нет» подтвердилась и оказалась не про код.
На подписке artemida из 50 нод отвечали 11. Измерено:

- 18 нод: сервер не отвечает ни на ICMP, ни на один порт.
- ~21 нода: TCP проходит, ClientHello уходит, ответа нет. Тот же handshake
  через рабочую ноду из Германии — 0.5 с. Значит рвётся между машиной и
  сервером.
- Фрагментация ClientHello (4/8/16/64 байта) не оживила ни одну.

Первая попытка измерить это была неверной: сокет из Python шёл через TUN, и
все 50 серверов выглядели доступными — через текущую ноду. Привязка к адресу
физического интерфейса — весь метод целиком.

Отсюда `yworld diagnose`: шлёт один и тот же коннект и TLS-hello дважды —
с физического интерфейса и через работающую ноду — и сравнивает, кто дальше
прошёл. Вердикты: работает / режет эта сеть / сервер недоступен / сервер не
отвечает.

### Ядро проверено и оставлено

Гипотеза «mihomo слабее по обходу блокировок, надо на sing-box» проверена
и **не подтвердилась**. Одни и те же 50 нод, пять конфигураций подняты
одновременно, каждая нода проверяется всеми ядрами в пределах секунды, порядок
ядер перемешан на каждой ноде:

| ядро | живых |
|---|---|
| mihomo | 10/50 |
| Xray | 11/50 |
| Xray + fragment | 11/50 |
| sing-box | 11/50 |
| sing-box + `tls_fragment` | 11/50 |

49 нод из 50 ведут себя одинаково. Фрагментация ClientHello не изменила ничего.

Три предыдущие попытки это измерить были негодными: сравнение с конфигом,
скачанным в другой момент, сравнивает разные серверы под одинаковыми именами;
поочерёдная проверка ядер меряет дрейф (mihomo дал 1/50 против собственных 8/50
через четыре минуты); фиксированный порядок ядер отдаёт победу первому, если
сервер принимает одно подключение за интервал.

Отдельно проверено и отвергнуто: групповой пинг **не** убивает ноды. Те же
десять нод — 4/10 поодиночке, 4/10 во время параллельного группового замера,
4/10 снова поодиночке. Кнопку «Пинг» трогать не нужно.

`yworld diagnose` на живой подписке (50 нод, 36 с): работает 11, режет эта
сеть 35, сервер не отвечает 4.

- Обрыв потока трафика теперь считается смертью mihomo: раньше оболочка часами
  показывала туннель, которого нет. Поток переподнимается через связанный флаг,

## Сессия 13: yshell

Оболочка получила имя — **yshell**, под пару к `~/yworld`. `y` от yorushi,
остальное слово на месте.

### Видеообои больше не замирают

Симптом был описан точно: обои встают при каких-то действиях и оживают при
других, например при переключении воркспейса. Причина оказалась не в декодере.

Оболочка считала долю закрытого экрана, суммируя площадь **всех** тайлов
воркспейса — включая колонки, уехавшие за край. Четыре открытых колонки
насыщали оценку до единицы, и видео вставало на любом занятом воркспейсе,
оживая на пустом.

Пауза при этом была хуже, чем просто пауза: оболочка плавно проявляла кадр,
вырезанный с первой секунды видео. То есть видимая полоска обоев не замирала,
а **прыгала на другой кадр** и застывала, а при возврате прыгала обратно.

Как теперь:
- Из того, что эта сборка niri сообщает честно, признак ровно один — тайл
  размером во весь вывод. Его получает только полноэкранное окно. Ни позиций
  тайлов (`tile_pos_in_workspace_view` всегда null), ни флага `is_fullscreen`
  в выдаче нет. Всё, что меньше полного экрана, продолжает играть: между
  тайлами и по краям всё равно видны обои.
- Пауза не меняет на экране ничего — `VideoOutput` держит последний кадр.
- Видимость считается по каждому монитору отдельно. Раньше все окна обоев
  писали в один общий флаг, и на двух мониторах закрытие одного останавливало
  другой.

### Цена обоев измерена и снижена

| | CPU |
|---|---|
| 1080p24 (исходник) | 20.7% |
| 720p24 (−56% пикселей) | 16.5% |
| 1080p15 (−50% кадров) | 13.3% |
| статичная картинка | 8.1% |

Кадры дороже пикселей примерно вдвое: платим за кадр (загрузка текстуры, обход
графа сцены, вывод), а не за декодирование. Поэтому `set-wallpaper.sh` **делит
частоту пополам и не трогает разрешение** — резкие обои на половинной частоте и
дешевле, и лучше, чем мыльные на полной. Именно пополам, а не до фиксированного
числа: неровный делитель — это и есть рывки (24 → 12 выбрасывает каждый второй
кадр и остаётся ровным, 24 → 16 чередовал бы промежутки в один и два кадра).
Подготовленная копия кэшируется по размеру и mtime исходника.

Итог: **12.1%** с видеообоями на весь экран.

Первые замеры давали разброс 13–21% на одном файле. Мерился переходный процесс:
каждая смена обоев пересобирает палитру и вся оболочка перекрашивается с
анимациями. Стенд `wallbench.sh` делает два прохода вперемешку с паузой на
успокоение — эти числа воспроизводятся.

### Экран блокировки

`WlSessionLock`, по поверхности на монитор, один разговор с PAM на всех:
аутентификация на каждой поверхности открывала бы по разговору на монитор и
считала неверный пароль дважды.

- Сервис `/etc/pam.d/yshell` — `auth include login`, той же формы, что у
  swaylock и hyprlock. Свой файл, чтобы блокировка не представлялась чужой
  программой.
- Проверено **до** того, как повешено на клавишу: неверный пароль возвращает
  `Failed`, а не `Error`. Это возможно только если PAM добирается до shadow
  через setuid-хелпер, а значит верный пароль вернёт `Success`.
- Разблокировки через IPC намеренно нет: оболочка на этой машине не должна
  уметь открывать физический экран. Аварийный выход — Ctrl+Alt+F2, вход,
  `pkill niri`.
- Фон — резкие обои, размытые на месте. Панельная размытая копия рассчитана на
  матовое стекло под островком бара (там от картинки ничего не должно
  оставаться) и на весь экран превращалась в кашу.
- Даты по-русски: сессия под en_US, и локаль по умолчанию печатала
  «Thursday, 30 July» под экраном, где всё остальное на русском.

`Super+Alt+L` — блокировка через оболочку, `Super+Alt+Shift+L` — swaylock на
случай, если оболочка не запущена.

### Цепочка простоя, которой не было

swayidle стоял в системе и никогда не запускался: экран горел вечно, сессия сама
не блокировалась.

Четыре ступени, потому что экран, гаснущий сразу из рабочего состояния,
неотличим от падения: приглушение на 4 минуте — это предупреждение, блокировка
на 8, мониторы на 9, засыпание на 20 и только от батареи. Блокировка **до**
выключения экрана, а не после, иначе рабочий стол на мгновение виден при
возврате.

### Лаунчер вместо fuzzel

fuzzel был единственной поверхностью на этом рабочем столе, которая явно пришла
со стороны: своя палитра, свой шрифт, своё представление о скруглении, и ничего
из этого не следовало за обоями.

Ранжирование осмысленное, а не по алфавиту: точное имя → префикс → совпадение на
границе слова → где угодно в имени → generic name → исполняемый файл, и лишь в
конце подпоследовательность, чтобы «fox» находил Firefox, но шум подпоследо-
вательностей не обгонял честный префикс. Ничьи разрешаются частотой запуска,
и она сохраняется между сессиями.

`Mod+D` — лаунчер, `Mod+Shift+D` — fuzzel.

### Язык оформления

В `Theme.qml` появилась шкала кеглей и три уровня теней. До этого каждый размер
был литералом: 12 и 11 встречались 78 раз на двоих, а 9/13/14/15/17/19 — по
разу-два. Так выглядит шкала, когда её нет.

Inter для интерфейса, Inter Display для крупного, табличные цифры на часах —
пропорциональные заставляли часы дышать при смене минуты и двигали соседние
виджеты.

### Бар

На светлых обоях островки растворялись в фоне: матовое стекло — это тонировка
поверх того, что за ним, и поверх светлого кадра видео разделять оболочку и
рабочий стол становилось нечем. Добавлены волосяная граница и блик по верхней
дуге — он и делает островок стеклом, а не скруглённым прямоугольником, лежащим
на картинке. Блик обрезается `ClippingRectangle`, потому что `clip: true` — это
прямоугольные ножницы, которые срезали бы его по краям.

Точки воркспейсов различают три состояния: активный — пилюля с номером,
занятый — залитая точка, пустой — меньше и полая. В подсказке число окон.

### Не сделано намеренно

**Гритер (вход в систему).** greetd настроен на `cage -s -- gtkgreet`, и
заменить его на свой на Quickshell (`Quickshell.Services.Greetd` в системе есть)
можно — но проверяется это только реальным циклом выхода и входа. Если что-то
не так, машина остаётся без возможности войти. Делать это, пока за ней никого
нет, нельзя. Нужен один logout/login под присмотром, минут пять.

## Сессия 14: рабочий стол как одна композиция

Отзыв был про вид и про взаимодействие, без подробностей. Поэтому мерилось не
по коду, а по снимкам живого экрана — и почти всё найденное уже было записано
в `Audit.md`, просто не сделано.

- **Правый край стола был четырьмя предметами, а не композицией.** Часы,
  спектр, три кольца и карточка плеера — разная ширина, разный левый край,
  разное оформление; глазу некуда идти. Теперь `WidgetRail`: одна мера (440 —
  ширина самой широкой части, карточки), один правый край, один вертикальный
  ритм, перетаскивается целиком. Свобода класть часы в один угол, а плеер в
  другой, потеряна — но в сохранённых настройках её никто и не использовал:
  все виджеты стояли на `x = 1` с чуть разным `y`, то есть этой же полосой,
  нарисованной от руки и слегка криво.
- **Кольца ЦП/памяти/температуры удалены** вместе с `StatGauge`. `BarLoad`
  показывает те же числа и только тогда, когда они кому-то нужны, и называет
  виновные процессы в своей карточке.
- **Секунды у часов убраны.** Самое крупное непрерывно движущееся пятно на
  столе несло меньше всего смысла; двоеточие и так пульсирует посекундно.
  `SystemClock` на столе и на обзоре переведены на минуты.
- **Спектр перестал исчезать.** Он теперь связка между часами и плеером: в
  тишине — дуга из точек (та самая «форма покоя», описанная в файле с самого
  начала и ни разу не показанная, потому что виджет гас вместе со звуком).
- **Третьи часы.** Бар, стол и дашборд показывали время одновременно. В слоте
  дашборда теперь история уведомлений — единственное, чего не было больше
  нигде, хотя панель для неё есть.
- **Тосты уезжали на часы.** Падали по правому краю прямо на цифры высотой
  112. Теперь падают из-под центрального острова — единственная свободная
  колонка, и она же честная: центральный остров и так «что происходит».
- **Страница «Столы» была пустой двухколоночной таблицей** — заголовок окна
  прижимался к правому краю, и на столе с одним окном между иконкой и её же
  подписью оставалось шестьсот пикселей пустоты.
- **Ladders.** 66 литеральных длительностей → 0. Добавлена группа «переход»
  (`animEnter/animArrive/animDrift/animDoze`) и `animTick` для колебания:
  переход — это не ответ оболочки и не холостой ход, и обе существующие группы
  были не той формы. Шкала кеглей получила `fontHeadline` и `fontIconHero`,
  10 внемасштабных размеров → 0. У гритера впервые появились свои лестницы
  (форма + движение), 17 длительностей и 2 радиуса → 0.
- **ВНИМАНИЕ: гритер не установлен.** `bin/yoake-greeter-install` требует root,
  а единственная настоящая проверка — выход и вход. Делать это, пока за
  машиной никого нет, нельзя (см. «Не сделано намеренно» в сессии 13).

## Сессия 14 (продолжение): три лестницы, одно свечение, три обрыва

- **99 внемасштабных альф оказались тремя разными вещами** под одним именем
  `Qt.alpha(Theme.x, n)`. *Заливка* лежит под содержимым — лестница была, но
  только в чернилах: акцент на 0.06 не видно вообще, и шесть файлов независимо
  дошли до 0.16/0.22/0.24/0.26/0.30. *Вуаль* лежит поверх содержимого, и
  лестница обрывалась на 0.20, поэтому каждый затемнитель придумывался заново.
  *Присутствие чернил* не имело рунгов вовсе. Теперь дрейф ноль во всех
  категориях, которые линтер умеет мерить.
- **`Glow.qml` — одно свечение.** Дело не в аккуратности: трое из четырёх
  анимировали `spread`, а это геометрия — каждый кадр перерисовывает размытие.
  `BarIsland` это измерил (4.4 пункта ядра), починил и записал; `MediaOrb`
  продолжал делать то же самое на размытии 48. Теперь рост — это трансформ.
- **Чтение яркости — не событие.** У `Brightness` был один сигнал на «пришло
  свежее значение» и «кто-то её подкрутил», поэтому открытие панели управления
  (которое как раз запрашивает чтение) выкидывало OSD поверх этой же панели.
- **`ScrollFade.qml`** — три списка обрывались без единого признака, что они
  прокручиваются: строка подписки, разрезанная краем панели, и шпаргалка без
  последней строки читались как сбой отрисовки. Не полоса прокрутки: каждая
  поверхность здесь — стекло поверх обоев, и рейка на нём — единственный
  элемент, который невозможно вписать.
- **Страница «Медиа» тратила 180 px ширины на украшение** — кот стоял по
  центру правого края, а колонка с треком была привязана к нему и выходила
  уже трёхсот пикселей. Кот ушёл в угол за содержимое.

## Сессия 14 (окончание): одно прибытие и два слепых пятна линтера

- **`Reveal` наконец получил вызывающих.** Шесть панелей писали одну и ту же
  пару opacity+scale с одними и теми же кривыми и разошлись на 0.88, 0.90,
  0.94 и `revealScale` — четыре ответа на вопрос, у которого один. Теперь это
  внутри `PanelChrome`: панель объявляет только угол, из которого растёт.
  Лаунчер сохранил падение и отдал масштаб — его вызывают клавишей, расти ему
  неоткуда, а ехать И масштабироваться это два движения (правило 1).
- **Линтер соглашался с тем, кто писал код, в двух местах.** Правило про
  длительности было привязано к концу выражения, поэтому
  `duration: open ? 180 : animExit` не видно вообще — литерал прятался внутри
  тернарника в лаунчере всё время, что существует проверка. Плюс 700 в
  селекторе обоев и два рукописных каскада `* 30`, для которых есть
  `Direction.stagger`. Правило про альфы смотрело только на базу `Theme.`, так
  что `Qt.alpha(root.color, 0.22)` не считалось — то же решение о цвете,
  который виджету передали, а не который он сам нашёл. Оба починены, оба сразу
  нашли настоящий дрейф.
- **Бар весь день носил два ярких ореола.** Дуга `BarIcon` при 100%
  замыкается в сплошное акцентное кольцо, а 100% батареи при 100% сигнала —
  это то, что ноутбук в розетке показывает почти всегда. То есть два самых
  неинтересных состояния были двумя самыми громкими пятнами в оболочке.
  Теперь дуга в полную силу, пока число стоит читать, и растворяется в
  собственной дорожке к верху диапазона.

## Сессия 14: наведение — это не просьба

- **Дашборд по наведению был ловушкой.** Задержаться на центральном острове
  420 мс — и открывался весь лист, **и** он забирал клавиатуру эксклюзивно.
  То есть проход мышью к трею мимо часов уводил клавиатуру у того, во что
  печатали, и оставлял лист, который надо было закрывать руками. Два
  последствия, о которых никто не просил, от жеста, который никто не делал
  намеренно.
  Теперь это **подглядывание**: `WlrKeyboardFocus.OnDemand` вместо
  `Exclusive` — клавиатуру не берёт, пока не кликнут, — и закрывается само,
  когда указатель ушёл и с острова, и с листа. Клик или клавиша повышают его
  до обычного дашборда. Проверено чтением, не указателем: гонять мышь на этой
  машине небезопасно (ydotool откалиброван неверно).
- `PanelChrome` раздавал содержимое через `inner.children`, а это принимает
  только Item — HoverHandler не грузился вообще, конфиг падал. Теперь
  `inner.data`, как в `MenuSurface` с самого начала.

- **Шпаргалка** ужата на рунг между разделами и теперь не влезает ровно на
  одну строку вместо почти целой колонки. Плотность на справочном листе — это
  и есть его смысл. Остаток требует, чтобы лист перестал центрироваться по
  вертикали и висел под баром, как все остальные панели: это смена характера,
  а не числа, поэтому записано, а не угадано.
- У `ScrollFade` в шпаргалке был лишний `anchors.margins: 24`, скопированный
  у Flickable, — затемнение рисовалось на 24 px выше того края, о котором оно
  говорило. И порог «есть ли ещё» поднят с 1 px до 3: список, чьё содержимое
  на два пикселя выше своей коробки, — это не список, который продолжается,
  это ошибка округления.

## Сессия 15: три вещи, которые требовали человека

### Бар как композитор — сделано

Открытый пункт `Direction.md`. Остров центрировался целиком, то есть на
середину бара ставилась **его середина**, — и часы уезжали вправо на половину
ширины плеера каждый раз, когда начиналась музыка, и обратно, когда она
кончалась. Часы читают по положению раньше, чем читают вообще: это
единственное на баре, что не должно двигаться, и это было единственное, что
двигалось.

Теперь центрируются часы, а остров растёт вокруг них: плеер открывает место
слева, ничего из уже стоявшего на экране не сдвигается. Правило 2, расписанное
арифметикой.

Намеренно без `Behavior`: `x` острова и позиция часов внутри строки считаются
одним и тем же проходом раскладки, поэтому меняются в одном кадре и часы стоят
абсолютно неподвижно, пока остров ширится под ними. Анимация здесь качала бы
часы на разницу двух кривых. Анимируется ширина плеера — она у `BarMedia` уже
своя, — и место открывается в его темпе.

### Экран блокировки — сделано и проверено

Настоящий дефект оказался не в каскаде, а рядом с ним: у героя (часы + дата)
`transform: Translate { y: entered ? 0 : 26 }` **без `Behavior`**. Значение
перещёлкивалось за один кадр, пока прозрачность рядом ехала 620 мс, — то есть
блок появлялся уже на месте и только потом проявлялся. Правило 4 ровно
наоборот: он прибывал и после этого не начинал двигаться. Подъём не играл ни
разу. Та же строка была и в гритере — это копия.

Проверено блокировкой при пользователе: экран рисуется, PAM отвечает,
разблокировка паролем работает.

Каскад пауз (`animFast` → `animNormal` → `animSlow`) оставлен **намеренно** и
не переведён на `Direction.stagger`. Стэггер рассчитан на списки: при темпе 220
он даёт 34/68/102 мс, а это целый экран, а не строка меню. Требование
`Direction` — чтобы смещения тянулись за темпом, — уже выполнено: рунги
`Theme.anim*` умножаются на `motionScale`.

### Гритер — установлен

`bin/yoake-greeter-install` выполнен, `/etc/greetd/config.toml` переключён с
`yshell-greeter` на `yoake-greeter` (копия до правки — `config.toml.pre-yoake`).
Проверено рендером установленной копии: обои, палитра, кот, часы, поле, кнопки
питания — всё на месте.

**Попутно нашлась настоящая поломка.** `set-wallpaper.sh` вызывает
`yoake-greeter-sync`, а установлен был только `yshell-greeter-sync` — вызов
стоит под `command -v`, поэтому молча не делал ничего. Палитра и обои гритера
не обновлялись с самого переименования: `colors.json` в `/var/lib` был от
5 августа. Теперь синхронизация снова живая.

**Старая установка оставлена как путь отката** и не удалена:
`/usr/share/yshell/`, `/usr/local/bin/yshell-greeter*`, `/var/lib/yshell-greeter/`.
Удалять — только после одного успешного выхода и входа. Если что-то пойдёт не
так: Ctrl+Alt+F2, вход в консоль, вернуть `config.toml.pre-yoake`. Сам
`yoake-greeter` к тому же откатывается на `gtkgreet` сам, если четыре запуска
подряд падают быстрее пяти секунд.

## Сессия 15: материал — это не решение Theme.qml

Вопрос «почему ты думаешь, что стекло это красиво» вскрыл настоящий баг, а не
разногласие о вкусе.

**Выключение мороза давало не плоскую оболочку, а прозрачную.** У `Surface`
заливка не-стеклянного состояния была одна на два случая, и по умолчанию это
6% чернил — верно для карточки, лежащей на панели, и не поверхность вообще для
панели, лежащей на обоях. Дашборд читался только за счёт блюра позади него, а
под блюром не было ничего. Это важнее вкуса: `Theme.frost` — переключатель,
который `Perception` дёргает **сам**, когда машине не хватает кадров. То есть
ровно в тот момент, когда оболочку нужнее всего прочитать, она растворялась.
Никто не видел, потому что никто ни разу не запускал шелл с выключенным
морозом.

Теперь у поднятой поверхности есть собственная земля, и она **непрозрачная**.
Не верхний рунг вуали: на 0.88 панель поверх терминала всё ещё показывает
терминал — то самое, ради чего крашеную поверхность и заводят, — и получается
стекло без блюра, худшая половина обоих материалов. Непрозрачную панель от
«чужой полосы поверх стола» спасает то, что `crust` выведен из палитры самих
обоев: слитность даёт цвет, а не просвет. Это и есть весь аргумент режима —
прозрачность лишь один способ выглядеть частью картинки, и он дорогой.

**Материал стал переключателем, а не решением.** Плитка «Стекло»
(матовое / плоское) в панели управления, `qs ipc call perception frost`,
сохраняется в `look.frost`. `Perception` теперь говорит только, может ли машина
позволить себе выбранный материал; какой он — не перцепция, а вкус.
